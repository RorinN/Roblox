# Pet Yeet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a published, playable Roblox game where you throw a pet as far as you can, with a timing meter, upgrades, a global leaderboard and two gamepasses.

**Architecture:** All game maths is pure Luau in `src/shared`, unit-tested with a tiny runner executed inside Studio. The server is authoritative: the client reports only *when* the player released the meter, never a distance. The client renders a calculated arc — there is no physics anywhere. Every tuning number lives in one `Config` module so playtest feedback maps to one edit.

**Tech Stack:** Luau, Rojo (source as files; the `.rbxl` is a build output), Roblox Studio MCP (`execute_luau`, `screen_capture`, `start_stop_play`, `character_navigation`), DataStore + OrderedDataStore, Blender + cuhkit, AnimKit, MapKit, UI Icon Pack.

**Spec:** `docs/superpowers/specs/2026-11-21-pet-yeet-design.md`

## Global Constraints

- **Must work on phones.** Input is tap-anywhere; all UI readable at phone width.
- **No real physics.** The flight is a calculated arc. Rejected approach A.
- **Server is authoritative** on distance and coins. The client sends release timing only.
- **Every tuning number lives in `src/shared/Config.luau`** and nowhere else.
- **Roblox free audio library only.** No custom audio uploads — account verification is unconfirmed and this must never block.
- **Source lives as files in this repo.** The place file is a build output, never the source of truth.
- **Fun with exactly one player in the server.** No feature may depend on a second player.
- **Analytics funnel wired in before publish**, not after: join → first throw → first upgrade → first purchase.
- **Exactly two gamepasses:** throw power, double coins. No luck pass, no randomness.
- `distance = base × throwPower × petMultiplier × timingMultiplier`
- Scope: one map, 3–4 pets, two upgrade tiers at launch. One-week target; rough but live.

## Review Focus

1. **A DataStore read that fails or throttles must not hand the player a fresh profile** that then overwrites their real save — this silently destroys progress and is the single worst failure here. *Test in Task 5.*
2. **A forged release time from an exploiting client** must be clamped, not trusted — cheatability is why approach A was rejected. *Test in Task 6.*
3. **A saved profile from an older version, or a partial table**, must load with missing fields defaulted rather than erroring. *Test in Task 5.*
4. **Phone input and small screens** — tap anywhere must fire the meter, and the HUD must not overlap or clip at phone width. *Test in Tasks 10 and 12.*
5. **Distances past float-display precision** must format as `1.2M`, never `1.0000000001e+15`. *Test in Task 3.*
